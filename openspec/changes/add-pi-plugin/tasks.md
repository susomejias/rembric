# Tasks — add the Pi harness as a fifth client

**The phase order is load-bearing.** Phase 1 adds assertions to code that has not moved yet; those assertions are only meaningful because they pass against the pre-extraction behaviour. Phase 2 moves the code they pin. Phase 3 writes the client that consumes the moved code. Phase 4 publishes. Phase 5 makes the client reachable and documented. Reordering 1 and 2 makes phase 1 assert what the extraction did rather than what the code did.

**Two hazards to hold in mind throughout, both measured:**

- `apps/plugin/.opencode-plugin/install.sh:78` rewrites exactly **one** import literal and its guard at `:82` `grep -qF`s exactly **one** destination. With a second shared import present the installer **exits 0 having written a plugin that cannot load**, and `install.test.ts:251-265` stays green because nothing in the suite ever loads the installed plugin.
- `pnpm run dev:docker:up` runs `seed-dev --reset` on **every** boot, from inside the container command where `package.json` does not show it. Do not smoke a pre-seeded corpus with it (see 6.4).
