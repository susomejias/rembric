## Why

`stop-nudge.sh` emits the end-of-turn summary reminder as `hookSpecificOutput.additionalContext` on the `Stop` hook (`apps/plugin/scripts/stop-nudge.sh:90`) on the premise — published in `plugin-session-protocol` and `claude-code-plugin` — that this channel is non-interrupting and "cannot hold a turn open". Measured against the shipped host (Claude Code 2.1.232), that premise is false: the `Stop` runner appends the hook's `additionalContext` to the very array it returns as `blockingErrors`, and the query loop treats a non-empty array as a block — it re-invokes the model with `stop_hook_active` set, increments a consecutive-block counter, and force-ends the turn with a user-visible warning once its default cap of 8 is exceeded. That warning, quoted verbatim in issue #343, tells the hook author exactly what is missing: "check `stop_hook_active` in the input and return success while it's true."

Nothing in the script bounds the loop. The cadence counter it gates on (`rembric_turn_count_peek rembric-turnnudge`, `:44`) is advanced only by `prompt-nudge.sh:34` on `UserPromptSubmit`, and a stop-hook continuation submits no user prompt — so `COUNT % 10 == 0` still holds on every re-entry, and the facts extraction over the whole transcript cannot become empty either. Measured with the shipped script at a cadence point: three consecutive invocations carrying `stop_hook_active: true` each emitted the full payload (1090 bytes with the unit-test transcript fixture, 2709 bytes with an 8.36 MB transcript — the bounded ceiling), while the control (turn 11, off cadence) emitted 0 bytes. `stop_hook_active` appears nowhere in `apps/plugin/` or `openspec/specs/` today.

The cost per firing turn — one turn in ten — is up to 8 forced model continuations, each re-injecting up to ~2.7 KB, each re-running the whole `Stop` entry list so `stop-sync.sh` re-POSTs `/summary` again, and each paying the reminder's own synchronous transcript parse before deciding to fire: 790 ms of hook wall-clock per invocation on an 8.36 MB transcript, on a path the host waits for. The turn then ends on a warning rather than on the model's own stop. A memory server is an optional accessory to its host; this is the failure mode the `proactive-save-nudges` change declined `Stop` to avoid, re-admitted by `ground-session-summaries` on an unmeasured premise (`design.md:49`) whose own Open Question 1 (`design.md:70`) had already identified `stop_hook_active` and dismissed it as "moot, because D4 does not block".

## What Changes

- **Honour the host's own loop guard, rather than inventing a second one.** `stop-nudge.sh` reads `stop_hook_active` from the stop event's stdin and emits nothing when it is `true` — empty stdout under Claude Code, `{}` under Codex, via the existing `_emit_nothing`. Rejected alternatives: a private per-turn statefile or a transcript-derived counter (reinvents a flag both hosts already send, and still fires once before converging); moving the reminder to some other non-blocking `Stop` channel (measured: on this host `additionalContext` IS the blocking path, and the async raw-sync entry cannot contribute feedback at all); withdrawing the end-of-turn reminder (throws away the placement `ground-session-summaries` exists for, to fix a one-line omission); raising the host's block cap (a host-side workaround that hides our defect and outlives it — deliberately neither used nor documented).
- **Place the guard first, before the config gate, the counter peek and above all the transcript parse.** A continuation must cost process start and nothing else: measured 790 ms → 5 ms of hook wall-clock per invocation on an 8.36 MB transcript. Source order is asserted by a test so a later edit cannot move the guard behind the parse.
- **One shared extractor in `apps/plugin/scripts/_api.sh`**, mirroring the boolean handling `rembric_session_ensure` already uses for `.created` (`:131-135`): jq-first, sed fallback, echoing `true`/`false`/empty. Claude Code and Codex are the only clients registering `Stop` and both invoke the same script, so one helper serves both — no per-client variant.
- **Fail open toward FIRING.** An absent, `null` or unreadable flag is treated as `false`, which is exactly today's behaviour. This is the one fail-open in the requirement that points at emitting rather than at silence, because treating an unknown flag as `true` would silence the reminder permanently on any host that does not send it.
- **Correct the spec text that asserted the measured-false property**, in both capabilities that carry it. The requirement's own header ("MUST NEVER interrupt") is renamed, not merely re-worded, because the mechanism it names is bounded rather than absent: the reminder costs at most ONE host continuation per cadence point. The existing assertion that no `decision` key is ever emitted survives unchanged — it is still true, and it was never what bounded the loop.
- **No manifest change.** No `SubagentStop` entry is added (none exists), the ordered `(script, async)` pair on `Stop` is untouched, and the three non-hook clients (opencode, Pi, Hermes) are unaffected — verified: each injects nudges at turn start only (`plugin.ts:235`, `index.ts:378`, `__init__.py:515`) and their end-of-turn handlers only schedule HTTP flushes.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `plugin-session-protocol`: state what the end-of-turn feedback channel actually does on the shipped host, bound the reminder to one host continuation per cadence point via `stop_hook_active`, require the guard to be decided before the transcript is touched, and record that this flag's fail-open points toward firing.
- `claude-code-plugin`: retract the "cannot hold a turn open" justification in the `Stop` requirement, record the measurement that replaces it, and add the reminder handler's loop-guard obligation plus a scenario with its control.

## Impact

- Plugin (single shared tree, all `Stop`-registering clients at once): `apps/plugin/scripts/_api.sh` (new `rembric_stop_hook_active_from_stdin_json`), `apps/plugin/scripts/stop-nudge.sh` (one guard line), `apps/plugin/test/stop-nudge.test.ts` (guard tests + controls + source-order assertion, and the reworded comment on the `never emits an interrupting decision` test whose stated premise is now known false).
- Docs: one `Stop`-hook loop-guard bullet in `.agents/skills/rembric-plugin-development/references/per-client-gotchas.md`, which today says nothing about `Stop`.
- Specs merged at archive time: `openspec/specs/plugin-session-protocol/spec.md`, `openspec/specs/claude-code-plugin/spec.md`.
- Deliberately untouched: `apps/plugin/hooks/hooks{,.codex}.json`, `apps/plugin/test/nudge-fixtures.json` (the `endOfTurnRubric` text is pinned and unchanged), `apps/server/**` (no server, HTTP, MCP or DB surface is involved), and the `.opencode-plugin/`, `.pi-plugin/`, `.hermes-plugin/` clients.
- Existing installations: no migration, no schema change, no derived-data invalidation (`memory_fts`, `memory_vec`, entity tables untouched), and no HTTP contract change. The append-only, scope-at-service, `topic_key` and judgment-freshness invariants are not involved. The change lands as a `plugin`-track version bump (any file under `apps/plugin/` bumps the one unified plugin version), which is also what makes it visible to Claude Code's version-keyed plugin cache. First run after upgrade behaves identically on a first stop event and stops re-firing on continuations. Rollback restores the loop and nothing else.
