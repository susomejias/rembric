tools/call latency, base (wire-base, origin/main f9f769e5, server 0.30.12) vs candidate (feat/mcp-stateless-single-handler, PR 3)

Instrument: end-to-end HTTP round trip of one JSON-RPC tools/call, measured client-side with
performance.now() around fetch() plus reading the full response body (measurements/latency.mjs).
Sequential calls from one Node 22.23.0 process on the same machine; POST to path-less /mcp.
Base: initialize once, then every call carries the minted Mcp-Session-Id (sessionful 2025 leg).
Candidate: initialize once, then every call carries no session id (stateless, one server per request).
Servers: `next dev` started by measurements/wire-diff/start-server.sh on localhost:3101 (base) and
localhost:3102 (candidate), fresh `mktemp -d` data, immediately after the PR 3 wire-diff run, so both
hold the same catalogue data. Embedder absent (FTS5 fallback), as in the harness.
Per tool: 30 warm-up calls discarded, then 300 measured calls. Two full runs, alternating base/candidate.
Arguments: memory.search {query: "wire diff"}; project.current {}.

Reading: the per-request server construction (createMcpServer + transport per request) costs about
0.2-0.5 ms at p50 and 0.3-0.7 ms at p90 on this instrument, i.e. +5-12% of a 3.5-4.4 ms round trip.
The 142.59 ms max in run 2 is a single outlier (p90 unaffected). `next dev` adds framework overhead
equally to both sides; absolute numbers under a production build would be lower.
