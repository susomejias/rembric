## 1. Backup storage primitive

- [ ] 1.1 Create `src/backup/storage.ts` exporting `BackupStorage` with `snapshot({ trigger, dataDir, db, schemaVersion })`, `list(dataDir)`, `rotate(dataDir, keep)`, `restore(dataDir, file)`. Internal helper `resolveTargetPath` rejects any path that does not resolve under `<dataDir>/backups/`.
- [ ] 1.2 `snapshot()` wraps `VACUUM INTO '<resolved-path>'` and the `consolidation_ops` insert in one `better-sqlite3` transaction. On any error inside the transaction the partial file SHALL be unlinked before the throw propagates.
- [ ] 1.3 Filename helpers: `auto-<ISO>.db`, `manual-<ISO>.db`, `pre-migration-<schemaVersion>-<ISO>.db`. ISO timestamps use `:` replaced by `-` for filesystem-friendliness.
- [ ] 1.4 `rotate()` reads the backups directory, filters to files with the `auto-` prefix, sorts by mtime descending, unlinks everything beyond the `keep` count. MUST NOT touch `manual-*` or `pre-migration-*`.
- [ ] 1.5 `restore()` validates the source path is under `<dataDir>/backups/`, renames `data.db` → `data.db.pre-restore-<ISO>`, copies the chosen file to `data.db`, writes `<dataDir>/restart_required` flag file with the snapshot filename inside.
- [ ] 1.6 Co-located tests in `src/backup/storage.test.ts` covering: path escape rejection (1.1), atomic rollback (1.2), filename shapes (1.3), rotation respecting trigger types (1.4), restore moves correctly (1.5).

## 2. Scheduler

- [ ] 2.1 Create `src/backup/scheduler.ts` exporting `class BackupScheduler { start(); stop(); }`. Mirror the shape of `src/consolidation/scheduler.ts` — `setInterval`-based with a clear `dispose` semantic, no overlapping runs (guard with a running flag).
- [ ] 2.2 Constructor reads env: `REMBRIC_BACKUP_INTERVAL_MS` (default `21_600_000`), `REMBRIC_BACKUP_KEEP` (default `7`), `REMBRIC_BACKUP_DISABLE` (default `false`). Validate that interval is ≥ 60_000 ms; reject lower values with a clear error at construction time.
- [ ] 2.3 `start()` short-circuits when `REMBRIC_BACKUP_DISABLE` is true, logs "auto-backup disabled" at info level, and SHALL NOT create the backups directory.
- [ ] 2.4 When enabled: ensure `<dataDir>/backups/` exists with mode 0700 (mirror the cold-start data-dir creation in `bootstrap.ts`), then `setInterval(() => storage.snapshot({trigger:'auto', ...}).then(() => storage.rotate(dataDir, keep)))`. Errors are caught and logged; one failed snapshot does not stop the scheduler.
- [ ] 2.5 Co-located tests in `src/backup/scheduler.test.ts` covering: disabled env short-circuits without filesystem side-effects, low-interval rejection, rotation called after each successful snapshot, error in snapshot does not halt the interval.
