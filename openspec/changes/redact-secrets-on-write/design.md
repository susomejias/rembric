## Goals / Non-Goals

**Goals:** one deterministic scanner, applied once, at the service boundary every client reaches; nothing derived ever sees the original span; the agent is told; a new persisted text column cannot ship unclassified.

**Non-Goals:** rewriting stored rows; configurable patterns; entropy heuristics; redacting read-only inputs (search queries, recall-hint prompts — never persisted).

## Decisions

### D1 — Redact in the services, before the repository call

The service layer is the one boundary MCP, HTTP and the dashboard all reach, and it is where `assertNoNul` already lives. Redacting there means the row is written redacted, so the FTS triggers, `extractEntities`, the embedder and both background workers — which all read the stored row — never see the original. Redacting in the MCP layer would miss the HTTP session routes; redacting in repositories would put content policy under the SQL boundary.

Order inside a write: the existing validation runs on the value AS SENT (emptiness, NUL, caps — every published contract is unchanged), then redaction, then the repository call. Server-composed text written into a redacted column is built from already-redacted input (the topic-key upsert reason quotes the redacted `topic_key`) or is a constant (the deadline-orphan reason).

### D2 — A closed list of named detectors, applied in a fixed order

The order is the table's: a key block first (its body contains base64 the others could match), structured tokens next, context-dependent shapes last. A span that already contains `[REDACTED:` is never matched again, so `GITHUB_TOKEN=ghp_…` counts once, as `github_token`, and redacting redacted text changes nothing.

`assigned_secret` is where false positives live, so it is the narrowest:

- **Key.** The key's words (split on `_ . -` and camelCase) must END in a credential word: `password`/`passwd`/`passphrase`/`secret`/`apikey` (also as a suffix, e.g. `PGPASSWORD`), `token`, `credential(s)`, or a two-word credential (`api key`, `access key`, `secret key`, `private key`, `signing key`, `encryption key`, `master key`, `account key`) or `secret key base`. A `token` qualified as non-secret (`page`, `next`, `prev`, `continuation`, `cancellation`, `sync`, `resume`, `cursor`, `eos`, `bos`, `pad`, `unk`, `sep`, `cls`, `mask`) does not count, nor do `tokens`, `token_id`, `topic_key`, `primary_key`.
- **Form.** `SCREAMING_KEY=value` (env files, shells); `--key=value` and `?key=` / `&key=` / `;key=` (flags, query strings); `key = "value"` / `key: "value"` / `"key": "value"` with a QUOTED literal. A lowercase key with an unquoted value outside a flag or query string is code (`Client(token=token)`), not a secret.
- **Value.** At least 8 characters and **secret-shaped** — it contains a letter and a digit, or it is an opaque run of ≥32 base64url characters with both cases. Code and prose literals assigned to credential-named keys are words (`credentials: 'same-origin'`, `password: "Required"`, `REFRESH_TOKEN = "refresh_token"`, `"login.password": "Passwort"`, `existingSecret: "postgres-credentials"`); credentials are not. It is also not a reference or placeholder: no leading `$ % < { [ ( @ * ~ / . #`; no `...`, `…`, `${`, `{{`; not one repeated character; not purely numeric or a boolean/null word; no placeholder hint (`example`, `placeholder`, `your`, `redacted`, `changeme`, `change_me`, `dummy`, `sample`, `todo`, `fixme`, `replace_me`, `insert_here`, `xxx…`) **starting at a word boundary** — inside an opaque token such hints occur by chance (`…gc6XXXE1…`) and must not exempt it; not a dotted code reference (`process.env.TOKEN`); not a file path (`*.pem`, `*.key`, `*.json`, …) or URL; not followed by `(`.

`authorization_header` applies the same secret-shape and placeholder rules. `url_password` applies the placeholder rules and also skips the literal words `password`, `pass`, `pwd`, `secret`, purely numeric values such as a port, a password equal to the user name (`guest:guest`), and env-variable names (`https://oauth2:PERSONAL_ACCESS_TOKEN@…`).

Rembric's own tokens have no prefix; they are caught where they are actually pasted — `REMBRIC_TOKEN=…`, `Authorization: Bearer …`, `?token=`.

### D3 — Placeholder `[REDACTED:<kind>]`

Typed so a reader (and the agent) knows what was there, short enough for titles. The whole matched span is replaced, except where a detector names the secret part (`url_password`, `authorization_header`, `assigned_secret`), which keeps the surrounding structure readable: `postgres://app:[REDACTED:url_password]@db:5432/x`.

### D4 — Caps after redaction

A placeholder can be longer than the span it replaces (an 8-character `assigned_secret` becomes 26 characters). Validation keeps running on the value as sent; when a placeholder lengthens a bounded field (memory/prompt/session title, topic_key, session summary) past its cap, the stored value is cut at the cap, never inside a surrogate pair. The cut can only shorten a placeholder or the text after it — the original span is already gone. The curated-summary merge checks its cap on the merge of the stored summary with the summary AS SENT, and the stored merge (of the redacted summary) is cut at the cap: a redaction never fails a write that would have succeeded without it. Rejecting instead would turn an automated write (HTTP hook titles and summaries are truncated to the cap by the client contract) into a lost write.

**Redaction precedes every server-side cut.** A cut made before the scanner runs can drop the context a detector needs (`…@host` of a URL, `Authoriz…` of a header, `DB_PASS…` of a key) and leave the secret undetectable. So `memory.capture_passive` derives each title from the redacted learning, and the HTTP session routes redact before `truncateSummary` (which keeps the tail) and `truncateTitle`. An invariant greps every call to `truncateSummary`, `truncateTitle` and `deriveTitle` in the scanned roots and fails unless the same line redacts; the dev seed script, which derives titles from fixed fixtures, is the one allow-listed file.

### D5 — Reporting

Each service write method takes an optional `RedactionTally` collector as its last parameter; redaction is unconditional, the tally only records it, so a caller that omits it loses the report and never the protection. MCP write handlers pass a tally and add `redactions: { kind, count }[]` (kinds in the D2 order) to their response when it is non-empty and the write stored something (a `memory.session_summary` discarded as `terminal_final` reports nothing); `memory.judge_batch` reports per result item, because each judgment carries its own reason. Responses with nothing redacted are byte-identical to today. HTTP session routes redact through the same services; their bodies do not change because no model reads them.

Each write tool's description gains one line (`REDACTION_NOTE`, 125 characters). `memory.session_summary` is the exception: its description measured 1868 of the 1900-character `DESCRIPTION_MAX_LENGTH`, and with the line it measured 1994. Its wording is pinned phrase by phrase by other requirements and tests, so instead of condensing that prose (or raising the ceiling, which issue #447 rules out) the line becomes the description of its `summary` argument. `tools/list` returns that argument description with the tool, and the tool's response already echoes the stored, redacted `summary` and `title`.

### D6 — Coverage invariant: classification plus a real-boundary sweep

A grep cannot prove that a value went through the scanner, so the invariant has two halves that only pass together:

1. **Classification** (`invariants.test.ts`): every TEXT column of every `SOURCE_TABLES` table in a freshly migrated database is listed in `TEXT_COLUMNS` (`schema-inventory.ts`) as `'redacted'` or with an exemption reason; an unlisted column, or a listed column that no longer exists, fails.
2. **Sweep** (`secret-redaction-sweep.test.ts`): every agent-facing write — the MCP write tools through the real route handler and SDK client, and the HTTP session routes — is called with a secret in every free-text argument. Afterwards the raw secret occurs in NO column of any table (including `memory_fts`, `prompts_fts` and `memory_entities`), the fake embedder never received it, and EVERY column classified `'redacted'` holds at least one placeholder — so a column cannot be classified `'redacted'` without a write path that reaches the scanner.

### D7 — Linear time

Content is uncapped, so the scanner must be linear: every regex anchors its start with a lookbehind that excludes its own body class (only run starts are tried), quantifiers are bounded, and no quantified group can split a run two ways. PEM blocks are found procedurally in one pass over the headers and one over the footers: footers are indexed by label and consumed with a per-label cursor, and a body is examined only up to the next header, so bodies never overlap. Evidence JSON is redacted as its serialized text (which also covers object keys and `"password": "…"` pairs), falling back to a structural walk only if a match crossed string boundaries and the result stopped parsing.

Vitest cannot interrupt synchronous code, so a timeout never fails a slow scan: the pathological-input tests (repeated headers, distinct-label headers, headers with a far `END`, long token-class runs, `KEY=` / `--k=` / quoted-key chains) assert a measured budget of 1,500 ms per 1.6M-character input with `performance.now()` around the `redactSecrets` call. Measured after the fix: 25–36 ms per input; before it, distinct-label headers took 7,330 ms and far-`END` headers 2,511 ms.

## Risks / Trade-offs

- **False negatives by design.** Lowercase unquoted assignments in prose (`password=hunter22`), YAML unquoted values, values under 8 characters, word-only passwords shorter than 32 characters (`correcthorsebattery`), `KEY = value` with unquoted values, INI/`.npmrc`/`X-API-Key:` forms and opaque tokens without context are not caught. Precision is the v1 contract; every observed false positive or negative becomes a corpus case.
- **A redacted title can lose its tail** (D4) in the rare case where placeholders lengthen it past 100 characters.
- **Already-stored secrets stay.** A read-only count in `memory.doctor` is the natural follow-up (issue #447).
