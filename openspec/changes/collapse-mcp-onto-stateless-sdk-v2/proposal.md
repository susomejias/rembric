## Why

The `/mcp` surface runs two MCP SDK majors and two protocol eras side by side: transports from `@modelcontextprotocol/server` 2.0.0 in front of an SDK 1.x `McpServer`, joined by an `as unknown as McpServerFactory` cast. That mix caused #446 (HTTP 500 on `server/discover`), and the fix that shipped is a guard that refuses 2026-07-28 clients rather than serving them (#455). The second leg cannot be dropped while Rembric keeps per-connection state keyed by `mcp-session-id`, and the 2026-07-28 revision removes that header and deprecates `roots`, the two things that state hangs off. This change removes the dependency on the transport session instead of porting it, so one stateless SDK v2 handler serves both eras.

## What Changes

- Port the tool server (`createMcpServer`, tool registration, error mapping) and every test client to `@modelcontextprotocol/server` / `@modelcontextprotocol/client` 2.4.0. `@modelcontextprotocol/sdk` 1.x leaves the repository, including the OAuth authorization server.
- **BREAKING** Serve both eras from one `createMcpHandler(factory)` in its default stateless posture. The hand-rolled sessionful 2025 leg (`serveLegacy`, `legacySessions`, `isInitializePost`) and the `-32022` refusal of 2026-07-28 requests are removed. The server no longer mints `Mcp-Session-Id`; `GET` and `DELETE` on `/mcp` answer `405`.
- **BREAKING** Remove project auto-detection: the server no longer issues `roots/list`, ignores `notifications/roots/list_changed`, and `project.current` no longer returns `suggestedSlugs`. The bridge stops relaying `roots/list` to the host. A path-less `/mcp` connection resolves to the default project, as it already does when roots yields nothing.
- **BREAKING** Remove the `project.use` tool, including project creation through `autocreate`. Projects are created from the dashboard only; `project_not_found` points there. `tools/list` goes from 25 to 24 tools (25 measured on `origin/main` by the wire harness).
- **BREAKING** `memory.session_start({project})` no longer activates a project; it asserts that the slug is the connection's resolved project and answers `scope_locked` otherwise.
- **BREAKING** Remove `SessionRouter`. A write attaches to the session named by an explicit, ownership-checked `sessionId`, else to the sole active session for the token and project (`findActiveForTransport`). `memory.session_resume` still resumes the Rembric session but no longer binds it to the connection. The Pi extension passes its own `sessionId` on every tool that declares one instead of binding with `session_resume`.
- Rewrite the OAuth authorization server (`/authorize`, `/token`, `/register`, `/revoke`, metadata) on Web `Request`/`Response`, replacing the 1.x Express router and its request/response shims. The wire contract of every OAuth endpoint is pinned before the rewrite and compared after it.
- Pin three behaviours that today live only in a manual smoke (RFC 6750 `WWW-Authenticate` on a missing bearer, `406` for a POST without the required `Accept`, SSE keepalive) with tests before the port, and add a differential wire check comparing every existing request shape against the base.
- Delete dead code that the above leaves unreachable: `packages/mcp/src/transport.ts` (`McpTransportManager`), `packages/mcp/src/roots-discovery.ts`, `RequestContext.mcpSessionId`, the bridge's 404 session-recovery path and the Pi `session_resume` bind loop.

Every behaviour below works today and stops working after this change. Everything not listed is preserved, in particular `.rembric` → `/mcp/<slug>` scoping, `project_not_found` / `scope_locked` isolation, bearer and OAuth access tokens, the post-auth rate limiter, body cap and DNS-rebinding gates, the HTTP session lifecycle (`/api/<slug>/sessions*`), `memory.session_*` tools, explicit `sessionId` attachment and cross-project reads for multi-project tokens.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `mcp-api`: transport becomes one stateless SDK v2 handler for both eras (no session id, `405` on `GET`/`DELETE`); `project.use` removed (tool list, `scope_locked` wording, authorization of `autocreate`); path-less resolution without roots; session attachment without `SessionRouter`; tool count 24. Four requirements whose scenarios pinned removed behaviour are removed and re-added under titles that state the surviving contract: "The MCP server MUST expose two project-management tools under the `project.*` namespace", "Every MCP tool call MUST be authorized against the token's scope for the resolved project", "Scope-sensitive tools MUST share the single scope resolver over the URL path and the default project" and "The MCP server MUST expose four session-lifecycle tools that keep no per-connection binding".
- `projects`: roots auto-detection, `roots/list_changed` refresh and roots-derived suggestions removed; agent-side project creation removed.
- `sessions`: `memory.session_start({project})` becomes an assertion; the project-switch guard and router-based precedence are removed, and the precedence requirement is re-added as "Session-tool handlers MUST resolve scope from the URL path or the default project only".
- `http-api`: HTTP-registered sessions reach MCP tools through `findActiveForTransport` and explicit `sessionId`, not through `SessionRouter`. The `Host`/`Origin` allow-lists match by hostname through the SDK's validation helpers and run before authentication; the `/mcp` body cap is the SDK's `maxRequestBodySize` and covers `POST` only, since `DELETE` answers `405` unread.
- `mcp-bridge`: no `roots/list` relay; no 404 session recovery; path-less fallback diagnostic names the fix. The compatibility-documentation requirement gains the scenario it was published without, which the rebuilt spec needs in order to validate.
- `pi-plugin`: session identity is declared per tool call through `sessionId`, not by binding the transport with `session_resume`; the transport-binding requirement is removed and re-added as "The Pi extension SHALL declare its session identity on every session-attaching tool call".
- `claude-code-plugin`: path-less fallback, new-slug bootstrap and manual-override text no longer describe roots or `project.use`.
- `mcp-oauth`: endpoints served without the SDK 1.x router with the observable contract unchanged; the one refusal that named `project.use` names `/mcp/<slug>` instead.
- `auth`: the `project.use` autocreate authorization clause is removed, and refusals no longer name `project.use`.
- `supply-chain-hygiene`: the bridge's zero-dependency rationale stops calling `@modelcontextprotocol/sdk` an `apps/web` dependency and stops citing the `roots/list` relay (delta written in PR 4, when it becomes true).
