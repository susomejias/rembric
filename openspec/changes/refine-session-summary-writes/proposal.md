## Why

A curated session summary is still being written as a report of the last turn, and each write deletes the sections the last turn did not touch.

Measured on the Pi session `01a00320-1fae-7360-862f-0ae866b38803`: **16 curated versions**. The `## Goal` lines of v12 through v16 name five different tasks and none of them subsumes its predecessor, so the sequence is five reports, not one refined state. `sessions.summary` ended as v16 — a CI formatting fix — after sixteen hours of work on the MCP bridge, and the session is labelled `Release-generated MCP manifest CI fixed`. The loss is concrete: v14 carried commit `01fdf55`, PR #352, `72/86 complete`, `26/26 specs` and `111 tests`; v15 carries none of the five.

**The cause is the write contract, not the storage.** Three facts, verified in this tree:

- The server validates a summary's LENGTH and nothing else. `assertSummaryWithinCap` (`apps/server/src/services/agent-sessions.ts:75`) is the only content precondition besides the empty/`NUL` checks, and it is called at `:339` (`writeSummary`) and `:386` (`end`). The six canonical headings are purely instructional — there is no parser anywhere on the write path.
- Every write that mutates `sessions.summary` funnels through one place: `precedenceSet` (`:792-804`) folds the value into the update `set`, and `updateAndVersion` (`:298-321`) applies it. The four other `updateById` call sites (`:461`, `:549`, `:574`, `:645`) write `status`/`ended_at`/`deleted_at`/`last_activity_at` only.
- **The same tool already has two opposite meanings for an absent field.** `precedenceSet` writes `title` only when the call carries one — `applyPrecedence` returns `changed: false` on `incomingValue === undefined` (`:774-780`), so an omitted title is "unchanged". An omitted `## Decisions+why` is "deleted". A model cannot infer which rule applies to which field, and the destructive one is the default for everything the model must retype.

So the model is asked, every turn, to reproduce a document it can no longer see, from a context window that has been compacted, with deletion as the penalty for forgetting a line. It does the thing the instruction literally describes — it writes what just happened — and the write is accepted, because nothing on the server distinguishes a refinement from a replacement.

This change fixes the contract: an absent section means "unchanged", the way an absent title already does, and the model-facing text stops asking for a turn report and starts asking for a refinement.

## What Changes

- **A `##` section absent from a curated write keeps its stored text.** The merged document is computed at the single precedence site (`precedenceSet`), section by section: a heading the write carries replaces that section outright, a heading only the stored value carries survives unchanged, a heading only the write carries is appended. This makes **partial writes** the point of the change — the model sends the two sections that moved and the other four are not at risk. Chosen over the two alternatives that were considered and rejected: a server-side reminder of what is stored (does not stop the deletion, only apologises for it), and a shrink guard that refuses a much shorter write (a correct summary legitimately shrinks — rejected on that ground once already in `2026-08-13-session-summary-full-rewrite`).
- **A curated write with ZERO `##` headings, against a stored summary that has at least one, is refused with `invalid_input`.** It is the one input the merge cannot interpret: there is nothing to match, and storing it would silently delete every stored section. The rejection is a matching rule, not a format validator — free-form storage stays accepted for a session that has no sectioned summary yet — and it closes the flat-paragraph regression path as a side effect, without the server ever parsing for the six canonical names.
- **A second cap check, on the merged value, because the stored value is no longer the argument.** `2026-08-13-session-summary-full-rewrite` kept that property deliberately and published the warning verbatim (`proposal.md:15`): _"Once the stored value is not the argument, one cap check stops being enough"_ — measured then at the HTTP boundary, where a composing write stored **10 350** characters against a 10 000 cap and returned `ok: true`. Its bullet at `proposal.md:27` — _"there is exactly ONE cap check … No second check is introduced, because the stored value and the argument are the same value"_ — is the sentence this change spends, knowingly. `SUMMARY_MAX_CHARS` stays 10 000 and stays the single source of truth; the argument check keeps its published position (before the row is read), and the merged document is checked immediately before it enters the update `set`.
- **A merge that exceeds the cap is REFUSED, never truncated.** The error names the merged length, the cap, and the action: condense the sections and resend. Silent truncation is the failure this whole line of work exists to stop — and `truncateSummary` keeps the TAIL (`agent-sessions.ts:52-68`), so on a sectioned document it would discard `## Goal` first. There is no wedge: sending all six headings replaces the whole document, so a condensed full rewrite always fits.
- **The model-facing frame moves from turn report to refinement.** Four obligations, stated where the model decides what to send: the write brings the stored state up to date rather than substituting for it; what is new is ADDED to what is there; **condense, never delete** — shrinking a section is legitimate compaction at a 10 000-char cap, making it disappear is loss, and a section that has genuinely emptied is written with an explicit `none` rather than omitted; and send only the sections that changed.
- **`title` is actively discouraged, not merely unrequested.** It is in the tool's signature, so a model fills it in unless told otherwise — which is how sixteen hours of bridge work came to be called a CI fix. The text says to send it on the session's first write, or when the stored title has stopped describing the work, and to omit it otherwise. **No code changes**: `title` is already optional and `precedenceSet` already preserves it when absent. No lock either — a real change of direction must still be able to retitle.
- **The text lands on the two server-owned surfaces plus one new shared constant, and no published cap is raised.** Measured on this tree: the `memory.session_summary` description is **1295** of `DESCRIPTION_MAX_LENGTH` **1900**, and a draft carrying every obligation above measures **1683** — it fits. `initialize.instructions` is **978** (unscoped) and **961** (scoped) of **1000**, so it can afford the merge sentence only if prose is reclaimed: with a 56-character shared rule and the non-normative preamble trimmed from 67 to 38 characters, the unscoped variant measures **978** again — zero net cost, cap untouched. The title guidance does NOT fit there alongside the merge sentence and lives in the tool description alone (measured: a draft carrying both puts the unscoped variant at 1039).
- **`SUMMARY_SECTIONS` is left byte-identical, and that is a budget decision.** Growing the shared section list would propagate to all eight surfaces pinned by `invariants.test.ts::"the session-summary rubric has one source"` and blow three published caps at once — the `summary` nudge fixture is 374 of 400 bytes, `postCompact` 675 of 700, `instructions` 978 of 1000. The refinement rule therefore ships as a SECOND exported constant in `apps/server/src/mcp/summary-rubric.ts`, consumed by the two surfaces that have room. The rubric file keeps its role as the one source; it now defines two things instead of one.
- **Out of scope, deliberately.** The nudge texts and their cadence (a later change owns them); the `session_summary_versions` table (a later change retires it — this proposal touches neither the table nor its schema, and rests no argument on its existence); any anchor-retention metric; any LLM; any new storage. **No client changes**: no protocol field, no per-client behaviour, no HTTP contract change. The one plugin file that moves is `apps/plugin/.hermes-plugin/__init__.py::system_prompt_block`, which an existing invariant requires to stay byte-identical to `instructions.ts::BASE`.
- **The nudge and command surfaces keep saying "REPLACES", and the deferral is safe rather than convenient.** Every one of them instructs the model to send the session's CURRENT COMPLETE state; under section-wise merge a complete document replaces every section, so the outcome those surfaces describe is exactly the outcome they get. They teach less than they could, not something false about what they ask for. A surface-by-surface rewrite belongs with the nudge change, which owns their byte budgets. Two published RATIONALES go imprecise as a result and are named here rather than left to be found — `plugin-session-protocol/spec.md:720` ("so sending the window alone stores the window alone") and `opencode-plugin/spec.md:309`, which argues from the same fixture text. Neither requirement is contradicted: both oblige a surface to SAY something, and the surfaces still say it.

## Capabilities

### New Capabilities

None. The behaviour lands inside existing capabilities.

### Modified Capabilities

- `sessions` — a new requirement for the section-wise merge (matching rule, ordering, the heading-less rejection, which writes merge and which do not); the cap requirement gains the second check on the merged value and the refuse-don't-truncate rule; the documented-structure requirement stops prohibiting the partial write it now licenses and carves the heading-less rejection out of "free-form storage remains accepted"; the version-row requirement's `exactly ONE cap check` scenario is corrected and the versioned value is named as the merged one.
- `mcp-api` — the `memory.session_summary` description obligations (merge semantics, partial writes, condense-never-delete, the `none` escape hatch, the merged-overflow error, `title` discouraged) and the `instructions` block's `SUMMARIZE` clause, both within their existing, unraised caps.

## Impact

**Server.** `apps/server/src/services/agent-sessions.ts` (merge at `precedenceSet`, second cap check, the two new `invalid_input` verdicts); a new pure module for the section parse/merge under `apps/server/src/services/` with a co-located test; `apps/server/src/mcp/summary-rubric.ts` (second exported constant); `apps/server/src/mcp/instructions.ts` (`BASE` SUMMARIZE clause + preamble reclaim); `apps/server/src/mcp/server.ts:326` (tool description); `apps/server/src/mcp/instructions.test.ts`, `apps/server/src/services/agent-sessions.test.ts`, `apps/server/src/test/mcp-integration.test.ts`.

**Plugin.** One file, forced by an existing invariant: `apps/plugin/.hermes-plugin/__init__.py::system_prompt_block` mirrors `instructions.ts::BASE` byte-for-byte (pinned by `apps/plugin/.hermes-plugin/tests/test_system_prompt_block.py`). No script, fixture, manifest or command file changes; `SUMMARY_SECTIONS` is unchanged, so the eight rubric-pinned surfaces and every published nudge byte budget stay exactly as they are.

**No schema change, no migration, no derived data.** `memory_fts`, `memory_vec` and the three entity tables are untouched. Nothing is backfilled and no stored summary is rewritten.

**Existing installations.** The first curated write after upgrade merges into whatever is stored. Two consequences are worth stating rather than discovering: a stored summary with no `##` headings (raw sync bodies, and any free-form curated one) is replaced exactly as today, because there is nothing to match; and a stale section that the model stops sending now SURVIVES instead of disappearing — omission preserves staleness, which is why "condense, never delete" and the explicit `none` are contract text and not style advice.

**Rollback.** Downgrading to a pre-change image restores whole-document replacement. Nothing stored becomes unreadable — the merged documents are ordinary Markdown in the same column — so rollback loses the semantics, never the data.

**Invariants.** Append-only memory: untouched (no `memory` row is written or deleted). Service-layer scope: untouched (the merge reads only the row the write already resolved). SQL confinement: the merge is a pure function in `services/`, and no repository or statement changes.
